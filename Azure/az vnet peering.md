## Peering

지연 시간이 없는 논리적인 직통 L3 링크

- **기술적 구현:** 완벽한 **L3 오버레이 가상화(Overlay Routing)** 기술 (호스트 간에는 IP 패킷으로 통신)
- **체감 효과:** 하지만 중간에 병목을 일으키는 홉(Hop)이 없고 연산이 호스트 단에서 이루어지기 때문에, 사용자가 느낄 때는 "성능 좋은 L2 터널링 인터커넥트"라고 느낄 수 있음

- **MAC 주소 유지:** 패킷이 건너갈 때 라우터(L3)를 거치면 원래 출발지 MAC 주소가 라우터의 MAC 주소로 변환되는데, 피어링은 이런 변환 오버헤드 없이 상대방에게 직통으로 전달됨.  
- **초저지연/고대역폭:** 중간에 패킷을 중개(L3 라우팅 처리)하는 중간 장비가 없다 보니, 물리적인 L2 스위치 한 대에 두 VM을 같이 연결한 듯한 성능을 체감.

- **IP 기반의 스마트 라우팅:** VNet 피어링은 L2 레이어에서 MAC 주소를 캡슐화해서 던지는 방식이 아님. Azure 물리 호스트(Hyper-V)에 탑재된 가상 스위치가 패킷의 **목적지 IP**를 확인함.
- **디렉토리 서비스(Directory Service) 조회:** 가상 스위치는 "어, 이 목적지 IP(`10.1.0.5`)는 피어링된 VNet B에 있네? 그럼 VNet B의 그 VM이 살고 있는 실제 물리 서버의 IP(`192.168.X.X`)가 뭐지?" 하고 Azure 컨트롤 플레인에 쿼리를 보냄.
- **호스트 간 직접 캡슐화:** 목적지 물리 서버의 위치를 알아내면, 패킷을 Azure 자체 내부 프로토콜로 감싸서(Encapsulation) 물리 네트워크를 통해 저쪽 물리 서버로 **L3 라우팅**하여 직송. 패킷을 받은 상대방 물리 서버는 껍데기를 벗겨 VM에게 전달함.
